10. Skill arguments

View this stage's code on GitHub →

A skill that always says the same thing isn't very useful — /deploy needs to know which environment. $ARGUMENTS captures everything typed after the skill name as one string; $ARGUMENTS[n]/$n pull out one positional argument by index. The substitution order matters more than it looks: $ARGUMENTS[0] is replaced before the bare $ARGUMENTS, because doing it the other way round would mangle $ARGUMENTS[0] into "<everything>[0]" the moment the bare pattern matched first.

Your task

  1. Parse everything after the skill name as whitespace-separated arguments.
  2. Substitute $ARGUMENTS (all of it, joined) and $ARGUMENTS[n]/$n (one positional argument) in the body before sending it.
  3. Replace indexed placeholders before the bare $ARGUMENTS — doing it in the other order mangles $ARGUMENTS[0].

Try it

Run this stage's own code:

just stage 10
cd .stages/10
# bundled skill "feed", body: "Feed the $0 some $1." + "Full request: $ARGUMENTS"
just run "/feed rabbit carrots"

Expect: Feed the rabbit some carrots. and Full request: rabbit carrots — each arg lands in its slot ($0 = rabbit, $1 = carrots) and $ARGUMENTS gets them all
